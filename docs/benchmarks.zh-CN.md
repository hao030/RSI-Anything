# 基准任务、实验设置与结果

[项目首页](../README.zh-CN.md) · [English](benchmarks.md)

RSI-Anything 在五个领域连接候选生成、后果预测与交互反馈。本页介绍论文中代码与 GUI 基准的实验设置和比较结果。

## 代码修复

Agent 从已有程序出发，根据测试反馈修改代码。ReasonFlux-Coder-7B 每轮提出四个修复候选，最多运行三轮，世界模型预测候选执行结果并指导选择。CodeContests 包含 200 道题，使用三个种子，共 600 次题目–种子评价；最终成功要求全部隐藏测试通过。

### APPS Introductory 与 LiveCodeBench

这两个实验检验修复流程在其他编程题集合上的表现。同一道题、同一个种子下，各方法共用初始程序和 ReasonFlux-Coder-7B 策略。公开测试反馈指导代码修改，全部公开测试通过时停止修复，最终依据完整官方测试集判定成功。

| 设置 | APPS Introductory | LiveCodeBench v6 |
| :--- | :--- | :--- |
| 题目数量 | 1,000 | 1,055 |
| 随机种子 | 0、1、2 | 0、1、2 |
| 题目–种子评价次数 | 3,000 | 3,165 |
| 每轮候选数 | 4 | 4 |
| 最多修复轮数 | 3 | 3 |
| RSI-Anything 完整测试通过率 | **46.37%** | **33.05%** |

报告指标为三个种子完整测试通过率的算术平均值。在相同代码策略和候选预算下，RSI-Anything 优于随机选择和容量匹配的静态验证器。图 2 的 **e–f** 展示这两项比较，**a–d** 展示修复流程、CodeContests 结果、预测质量和反馈开销。

## GUI 交互

Agent 观测界面、提出动作、依据后果预测选择行动，并从环境获得任务反馈。交互中保留的改进继续指导后续决策。

### MiniWoB++

浏览器工作流使用 `click-checkboxes`：选中指令指定的复选框并提交表单。三个保留控制器版本在同一组 100 个测试任务上评价，每次限时 120 秒、最多八个动作。

| 指标 | 初始版本 | 中间版本 | 最终版本 |
| :--- | ---: | ---: | ---: |
| 任务成功率 | 51% | 79% | **99%** |
| 平均每次任务动作数 | 5.30 | 2.93 | **3.21** |
| 错误提交任务数 | 9 | 21 | **1** |

最终控制器的平均动作数较初始版本减少 **39.4%**，重复点击由 **237 次降至 0 次**。中间版本动作更少，但错误提交更多，因此动作数需要结合任务成功率和提交错误一起解读。

### OSWorld

OSWorld 在桌面任务中评价 GUI Agent。论文比较初始 Agent、RLAnything 与 RSI-Anything 的任务成功率：模型预测指导动作选择，环境反馈支持后续交互中保留的改进。

| 方法 | 相对初始 Agent 的成功率提升 |
| :--- | ---: |
| 初始 Agent | 比较基准 |
| RLAnything | +12.3% |
| RSI-Anything | **+18.4%** |

RSI-Anything 的成功率还比 RLAnything **相对提升 5.5%**。相对提升计算为 `100 ×（方法成功率 / 参考成功率 − 1）%`：表格统一以初始 Agent 为参考，5.5% 的比较以 RLAnything 为参考。
