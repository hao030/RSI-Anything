## 一、我最想做的 topic：自我改进的瓶颈在「自评」

**一句话**：RSI 能不能转起来，取决于模型对自己输出的判断是否可靠。在代码、数学这类有执行器或标准答案的领域，这个问题被外部验证器绕开了；但在感知和具身这类没有验证器的场景，自评就是最薄弱的一环。

这批工作都围绕「信号从哪来」展开：

| 信号来源 | 代表工作 | 问题 |
| :--- | :--- | :--- |
| 外部执行器（代码运行、测试用例） | Absolute Zero、Darwin Gödel Machine | 可靠，但只适用于可验证领域 |
| 多数投票 / 一致性 | TTRL | 模型系统性错误时，投票会把错误放大 |
| 模型自己当评委 | Vision-SR1、Self-Rewarding | 容易自我高估、出现 reward hacking |
| 自问自答（self-play） | VisPlay、Vision-Zero、RISE | RISE 指出出题质量会下降、题型会收窄 |
| 世界模型预测后果 | RSI-Anything、Dream-RSI | 预测本身准不准，很少被单独评测 |
| 不确定性 / 置信度 | Ranked from Within | 只做了排序，没有放进自我改进闭环 |

这个 topic 的好处：
- **资源少**：核心问题是「测」和「选」，大部分实验只需要推理；
- **新**：多模态、低空、具身场景下的自评可靠性几乎没人系统做过（见第二部分检索结论）；
- **和 T 老师的项目天然契合**：无人机和灾害场景恰好都缺标签、缺验证器。

## 二（续）、和 T 老师项目的结合点

### 1. 端侧智能感知无人机

- **痛点**：端侧只能跑小模型；野外没有标签；高度、天气、光照一变就有分布偏移。
- **RSI 能带来的价值**：
  - **端云协同的自我改进闭环**：端侧小模型根据自己的置信度决定哪些样本上传，云端大模型给伪标签，定期把改进推回端侧。这就是 RSI 的 Propose → Evaluate → Learn → Retain，只是分布在端和云两侧。
  - **知道自己什么时候不行**：自评可靠的话，端侧就能在没把握时减速、悬停或请求人工，这对安全很关键。

### 2. 具身长程任务

- **痛点**：步骤一多，前面的小错误会累积；有些动作执行了就撤不回来。
- **RSI 能带来的价值**：
  - **执行前先预测**：用世界模型预测每一步的后果，提前拦住不可逆的错误动作，这正是 RSI-Anything 的思路。
  - **经验库自我进化**：每次任务结束后把成功经验、失败教训沉淀成技能和规则，下次直接复用。完全不用训练，只需要 API 调用。

### 3. 低空灾害检测

- **痛点**：灾害少见，每次灾害的样子都不一样，现场几乎没有标签，而且漏检的代价很高。
- **RSI 能带来的价值**：
  - **无标签选模型**：新灾害一来，用不确定性信号（Ranked from Within 的思路）判断现有哪个模型在这批图像上最可靠，再决定部署哪个。
  - **在现场图像上自适应**：用自问自答或伪标签在新灾害图像上快速适应。但前提是自评可靠，所以要先评估清楚。
  - **校准**：灾害场景里模型说「没有受损建筑」时，它有多大把握？校准不好直接影响救援决策。

> 其他项目我还不了解，补充后可以再对应。

## 三、Idea 列表（按可行性排序：资源越少、越新、做的人越少越靠前）

### Idea 1：低空场景下 VLM 自评可靠性 Benchmark ⭐ 首推

- **问题**：在无人机 / 灾害图像上，VLM 知不知道自己什么时候错了？自评、自奖励、多数投票、置信度这几种信号，哪种在低空场景还靠得住？
- **做法**：
  - 把 RescueNet、FloodNet、OpenFly 等已有标签自动转成问答题（计数、受损程度、定位、导航指令理解）；
  - 测十来个 VLM（开源小模型本地跑 + 几个 API 模型）的准确率，以及它们各种自评信号的可靠性：校准误差、自评和真实对错的相关性、多数投票在系统性错误时是否失效；
  - 重点对比地面图像和航拍图像：同一个模型，自评在航拍场景下会不会明显变差。
- **资源**：只需推理，几张消费级显卡或 API 即可。
- **新颖性**：自我改进相关工作都默认自评可用，但没人在航拍场景验证过；灾害 VLM 评测又以卫星图为主。
- **和项目的关系**：三个项目都能用上，是后面几个 idea 的地基。
- **风险**：题目太简单拉不开差距，需要多设计需要推理的题型。
- **第一步**：选 RescueNet，自动生成 200 道题，用 3 个模型跑 pilot，看自评信号和真实正确率的相关性。

### Idea 2：灾害场景的无标签模型选择

- **问题**：一场新灾害发生时手上没有标签，怎么从多个候选模型或检查点里选出最可靠的那个？
- **做法**：把 Ranked from Within 的不确定性排序方法搬到航拍灾害数据上，按灾害类型（洪水、飓风、地震）做跨事件验证：无标签排序结果和真实排序是否一致。
- **资源**：只需推理。
- **新颖性**：原方法只在通用 VQA 上验证过；灾害场景分布偏移大，结论不一定成立，无论成立与否都有信息量。
- **风险**：工作量偏小，可能更适合作为 Idea 1 的一部分或一篇 workshop 论文。

### Idea 3：免训练、靠经验自我进化的无人机长程任务智能体

- **问题**：无人机执行多步任务（巡检、搜救、找目标）时，能不能只靠积累经验、不更新参数，就越做越好？
- **做法**：基于 AerialClaw 或 OpenFly 环境，给智能体加上经验库 / 技能库（ExpeL、Reflexion 式），可选地在执行前用 VLM 预测这一步的后果；记录多轮任务的成功率曲线，分析什么时候会改进、什么时候会停滞或变差。
- **资源**：API 调用 + 仿真器。仿真器渲染需要一张显卡，要先确认环境能跑起来。
- **新颖性**：无人机上的自我进化工作很少，现有工作也缺少对改进曲线的系统分析。
- **风险**：仿真环境搭建可能耗时，第一周先确认能跑通。

### Idea 4：基于置信度的端云协同自我改进

- **问题**：端侧小模型资源有限，怎么用最少的上传量和人工标注持续变好？
- **做法**：用数据流模拟部署过程：端侧小 VLM（2–3B）按自评置信度挑选上传样本，云端大模型打伪标签，周期性 LoRA 微调回推。对比随机上传、全部上传、按置信度上传的效果和通信开销。
- **资源**：需要少量 LoRA 训练，单张 24GB 显卡可以覆盖 2–3B 模型（需实测确认）。
- **新颖性**：端云协同和自我改进各自都有人做，结合到无人机感知上的少。
- **风险**：需要训练，周期比前三个长；依赖 Idea 1 的结论（自评可靠才能这样挑样本）。

### Idea 5：航拍图像上的自问自答自我进化

- **问题**：VisPlay、Vision-Zero 这类自我博弈方法在航拍图像上还有效吗？
- **做法**：在无标签航拍图像上，用小 VLM 跑 VisPlay 式的出题 + 答题循环，再在灾害和导航任务上评测。
- **资源**：需要 RL 训练，是五个里最重的；即使用 3B 模型也要几张显卡跑几天（需估算）。
- **新颖性**：领域新，但方法本身是现成的，容易被认为只是换数据集。
- **风险**：资源和撞车风险都最高，建议放在最后，等 Idea 1 的结论出来再决定。

### 汇总

| # | Idea | 资源 | 新颖性 | 竞争者 | 是否需要训练 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 1 | 低空 VLM 自评可靠性 Benchmark | 低 | 高 | 少 | 否 |
| 2 | 灾害场景无标签模型选择 | 低 | 中 | 少 | 否 |
| 3 | 经验自我进化的无人机长程智能体 | 中低 | 高 | 少 | 否 |
| 4 | 置信度驱动的端云协同自我改进 | 中 | 中 | 中 | 少量 LoRA |
| 5 | 航拍图像自问自答自我进化 | 高 | 中 | 中 | RL |

**建议路线**：先做 Idea 1（可以把 Idea 2 并进来），2–3 周出 pilot 结果；结论成立后，Idea 3 和 Idea 4 都可以把它当成动机和组件。
